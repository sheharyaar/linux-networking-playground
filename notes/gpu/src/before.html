Before you start: prerequisites and benches

The goal is three sentences you can say and prove. The first: I can write a CUDA kernel, read its PTX and SASS, and say from the numbers whether it is limited by arithmetic or by memory. The second: I can explain how bpftime turns an eBPF program into PTX inside someone else's kernel, well enough to add a helper. The third: I can say where the time to the first token and the time per token go in an LLM server, and which call or kernel to probe for each. Here is what those sentences rest on, and where each piece is taught.

The three benches

@@BENCHES@@

Lab prerequisites (you install these; the document never does)

  • Turn the laptop GPU on. supergfxctl -m Hybrid, log out and in, then nvidia-smi -L should list one GPU. The nvidia-open-dkms module must have built for the running kernel.
  • Nsight Systems and Nsight Compute, for the tooling chapter only. They are not part of Arch's cuda package.
  • bpftime in ~/workspace/repos/bpftime: git submodule update --init --recursive, then cmake -Bbuild -DBPFTIME_ENABLE_CUDA_ATTACH=1 -DBPFTIME_CUDA_ROOT=/opt/cuda and cmake --build build -j. Its CMake downloads Frida. Upstream says it is tested with CUDA 12.6; this laptop has 13.4, so the first build is also a test.
  • vLLM: a uv virtual environment on Python 3.12 or 3.13 (the system Python is 3.14, which vLLM does not list), then uv pip install vllm.
  • llama.cpp in ~/workspace/repos/llama.cpp: cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=89 and cmake --build build -j. Name the architecture: by default ggml builds for native, and nvcc then embeds no PTX, which a bpftime probe needs. 89 with no suffix embeds both PTX and SASS for the laptop; use 61 on the P5000 (with a CUDA 12.x toolkit) and 90 on the H100.
  • One small model: Qwen/Qwen2.5-0.5B-Instruct for vLLM, and Qwen/Qwen2.5-0.5B-Instruct-GGUF for llama.cpp. Both are Apache-2.0 and ungated.
  • For Pascal SASS only: a CUDA 12.x toolkit installed next to 13.4. CUDA 13 cannot target Pascal at all.

Conventions

Source citations look like attach/nv_attach_impl/nv_attach_impl.cpp:1224 and are pinned to the commits in the footer; the clones live in ~/workspace/repos. The kernels, probes and scripts the labs use are in lab/gpu/ next to this file. Every listing labelled with a compiler and an architecture was produced by that compiler for that architecture.
