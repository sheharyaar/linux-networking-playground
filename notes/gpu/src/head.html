How to read this

This document teaches four things in one line of argument: how an NVIDIA GPU runs a program; how to write that program in CUDA and read it again as PTX and SASS; how bpftime puts an eBPF program inside a GPU kernel you did not write; and how a large language model server uses the GPU to produce text, so that you know where to point those probes. It follows one matrix-vector multiply from the first chapter to the last.

Path 1: straight through. The intended way. Every chapter builds on the ones before it, and each one moves the same multiply one step further: from silicon, to source, to machine code, to a running kernel, to a probe inside it, to a token on a screen. About @@MIN@@ minutes.
Path 2: hop by layer. Already own a layer? Use the coloured tags. HW silicon and memory · ISA PTX and SASS · CUDA programming model, toolchain, runtime · TOOLS profilers and debuggers · EBPF bpftime and eBPF on the GPU · LLM language models and the servers that run them.

The vocabulary rule. Every term of art appears in bold at the place it is defined, and never before. If you meet a word you do not remember, search backwards: its definition is behind you, and the merged glossary at the end lists every term by chapter. The document assumes you know Linux systems programming and kernel eBPF well. It assumes no GPU knowledge and no machine-learning knowledge. Two sibling dossiers in this folder go deeper on neighbouring ground, and chapters link to them where they help. They are optional.

Three benches. Every hardware chapter ends with a small dated table comparing three NVIDIA generations, because three real machines are in play. The laptop has an Ada GPU and is where every lab in this document runs. An H100 (Hopper) arrives later. A customer runs a Quadro P5000 (Pascal). Listings are real compiler output from this laptop, unless a listing says it is illustrative: nvcc 13.4 for Ada and Hopper, and clang 22 for Pascal PTX. A runtime number marked expected was not measured.

Check yourself, and how to use it. Every chapter ends with two or three questions, and each one carries its answer behind a toggle. Answer out loud first, in full sentences, and only then open it. A question you can half-answer is the one worth re-reading the chapter for. One question in most chapters gives you an observation and asks what happened. Those are the ones that test whether a mechanism will come to mind when you need it. If you would rather be quizzed properly, hand this file to an agent running the Alvar probe skill and ask it to quiz you chapter by chapter: it asks through a real question tool, scores your reasoning rather than your letter, and writes what it found to .alvar/maps/.

Diagrams. Every diagram has a zoom button in its corner. It opens the picture full screen: scroll to zoom, drag to pan, double-click to fit, Esc to close.
