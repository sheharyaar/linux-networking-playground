Glossary

Every term defined in the document, grouped by the chapter that introduces it and in reading order. A term appears once, under the chapter where it is first defined; if you meet it earlier than that, it was being named rather than taught. Each heading links back to its chapter.

Chapter 0 · Prologue · The chart, the skb, and the tracer

skb, socket buffer
struct sk_buff: the metadata block describing one packet, pointing at a separate data buffer.
net_device
Any interface the kernel can transmit through, real or virtual, with an ndo_start_xmit function.
receive handler
A function pointer on a device, consulted in the L2 receive loop; bridges, bonds and macvlan use it to take frames.
network namespace, netns
A private copy of devices, routes, netfilter tables and sockets. Printed as an inode by pwru.
netfilter hook
One of five points where IP code calls nf_hook with a continuation; entries are walked in priority order.
verdict
What a function on a hook's list returns: accept, drop, stolen, queue.
kprobe
A breakpoint at a function entry that runs a program and lets the function continue.
pwru
Kprobe-based tracer printing one line per skb per kernel function, filtered with tcpdump syntax.
bpftrace
One-line kprobe programs on functions you name.
nft monitor trace
Rule-by-rule report of chains an skb with nf_trace set passes through.
ftrace function_graph
Kernel call-tree tracer with timing, driven through tracefs.

Chapter 1 · Birth of an skb: the NIC, the interrupt, NAPI, and the backlog

receive ring, descriptor
Circular array of records, each pointing at a buffer; the card writes frame lengths into them.
DMA
The card writing frame bytes into RAM without the CPU.
page pool
Per-ring recycling allocator of DMA-mapped page fragments for receive buffers.
hardirq
The interrupt handler proper; runs with interrupts off; here it only schedules NAPI.
softirq, NET_RX_SOFTIRQ
Deferred work with interrupts on; the receive softirq's handler is net_rx_action.
NAPI, poll, weight
Interrupt once, then poll the ring up to weight (64) frames per call.
budget, time squeeze
net_rx_action's limits: 300 packets or 2,000 us; exceeding them increments time_squeeze.
GRO
Generic receive offload: merging consecutive same-flow segments into one skb inside the poll.
backlog, softnet_data
Per-CPU queue input_pkt_queue plus a fake NAPI; filled by netif_rx, drained by process_backlog.
netif_rx
The entry for callers already holding an skb; queues into the backlog.
RSS, RPS
Hardware and software spreading of flows across CPUs; RPS uses another CPU's backlog.

Chapter 2 · XDP: the hook that runs before the skb exists

XDP
eXpress Data Path: a BPF program run on a received frame before the skb is built.
xdp_buff
The program's view of the frame: data start and end, metadata area, buffer size, receive queue.
XDP verdict
XDP_PASS, XDP_DROP, XDP_TX, XDP_REDIRECT, XDP_ABORTED.
native, generic, offload
Where the program runs: in the driver poll, at the top of the core receive loop, or on the card.
XDP_PACKET_HEADROOM
The 256 bytes of free space in front of the data that a program is promised; generic mode copies to get it.
xdp_frame
An xdp_buff converted for queueing, stored in the buffer's own headroom.
devmap, cpumap
Redirect targets: another device's transmit path, or another CPU that builds the skb there.
AF_XDP
A socket that receives redirected frames in user space with no skb; named here only.
skb_pp_cow_data
Copy an skb's bytes into a page-pool buffer and build a new skb; what veth does before native XDP on a cloned skb.

Chapter 3 · L2 receive: taps, tc ingress, the receive handler, and the protocol demux

__netif_receive_skb_core
The one function every received skb passes through; a loop of stations with an another_round label.
packet socket, packet type, ptype_all
An AF_PACKET socket registers a handler on the list of taps; packet_rcv clones the skb for it.
deliver_skb
Bumps skb->users and calls one tap or protocol handler.
promiscuous mode, PACKET_OTHERHOST
Accept frames for other MACs; they reach the taps and are dropped by IP on pkt_type.
dev_queue_xmit_nit
The transmit tap, cloned just before the driver is called.
tc ingress, clsact
The station at lines 6062 to 6070; clsact is the per-device holder of classic ingress and egress filters.
tcx
BPF link attachment for tc programs, run first by tcx_run; classic filters run only if it returns unspecified.
tc verdict
TC_ACT_OK, TC_ACT_SHOT, TC_ACT_REDIRECT, TC_ACT_RECLASSIFY.
vlan_do_receive
Untag and rewrite skb->dev to the VLAN sub-device, then loop.
RX_HANDLER_CONSUMED, ANOTHER, EXACT, PASS
The four return codes of a receive handler; consumed exits the loop, another loops with a new device.
ptype_base, pt_prev
The protocol hash keyed by skb->protocol, and the deferred-delivery trick that gives the last handler the skb without a clone.

Chapter 4 · L3 receive: ip_rcv, PREROUTING, and the routing decision

ip_rcv_core
Header validation, scratch-space reset and skb_orphan; the function before the PRE_ROUTING hook.
skb_orphan, destructor
Detaching an skb from its owning socket by running the socket's accounting callback (tcp_wfree, sock_edemux).
early demux
Looking up an established socket before routing so its cached route can be reused.
ip_route_input_slow, fib_lookup
The normal input route lookup: policy rules pick a table, the FIB trie gives the longest prefix match.
FIB
Forwarding information base: the routing table as the kernel stores it, a level-compressed trie.
RTN_LOCAL, RTN_UNICAST
Route types: one of my addresses, or somebody else's.
dst_entry, skb_dst
The route object attached to the skb, carrying the input and output function pointers and the next hop.
dst_input, dst_output
The indirect calls through the route's pointers; the routing diamond of the chart.
fib_validate_source, rp_filter
Reverse-path check on the source address at input.
ip_local_deliver, ip_protocol_deliver_rcu
Door one: LOCAL_IN hook, then dispatch by protocol number to tcp_v4_rcv and friends.
ip_forward, skb_cow, ip_forward_finish
Door two: TTL check, private header, FORWARD hook, then the route's output function.
ip_error
The input function of a route that cannot be forwarded; counts IpInAddrErrors and drops silently when forwarding is off.

Chapter 5 · Netfilter and conntrack: hooks, priorities, tuples, and NAT

hook entry, priority
A function pointer plus an integer; entries are walked in ascending order by nf_hook_slow.
base chain
An nftables chain bound to a hook and priority; registered as one hook entry running nft_do_chain.
tuple
Source address, destination address, protocol, source port, destination port; the conntrack key.
conntrack entry, nf_conn
The tracked connection: original and reply tuples, status bits, timeout.
reply tuple
The tuple a returning packet must match; rewritten by NAT, mirror of the original otherwise.
ctinfo: NEW, ESTABLISHED, RELATED, ESTABLISHED_REPLY
The classification packed into skb->_nfct next to the entry pointer.
unconfirmed, nf_confirm
An entry exists but is not in the hash table until the last entry at POST_ROUTING or LOCAL_IN inserts it.
nf_nat_inet_fn
The one function behind all four NAT hook entries: run nat chains on the first packet, then rewrite from the mapping.
nf_nat_setup_info, nf_nat_manip_pkt
Choose the mapping and store it in the reply tuple; rewrite one packet's header and checksums.
nftrace, nf_trace
The bit a rule sets on the skb so every later chain reports its rule walk to nft monitor trace.

Chapter 6 · Transmit: from sendmsg to the wire, through the default gateway

write queue
The socket's list of unacknowledged skbs; TCP transmits clones of them.
ip_queue_xmit, __ip_local_out
Attach the cached route, write the IP header, call LOCAL_OUT, then dst_output.
ip_output, ip_finish_output2
POST_ROUTING hook, then fragmentation or segmentation decisions, then the neighbour step.
neighbour entry, NUD states
One row of ip neigh: address, MAC, and INCOMPLETE, REACHABLE, STALE and friends.
arp_queue, neigh_probe, arp_solicit
Where an unresolved packet waits, the function that triggers resolution, the function that sends the ARP request.
__dev_queue_xmit, netdev_core_pick_tx
The device transmit entry; tc egress, then choose the transmit queue.
queueing discipline, qdisc, noqueue
The object that orders and holds packets before the driver; virtual devices have none.
qdisc bypass, __qdisc_run, sch_direct_xmit
Skip an empty qdisc; otherwise drain it in batches of 64 to the driver.
GSO, TSO
Build one large skb and segment it late, in software or in the card.
ndo_start_xmit, transmit completion
The driver's entry that writes descriptors, and the later poll that frees the skb.

Chapter 7 · The socket is a file: from sk_receive_queue to recvmsg

struct socket, struct sock
The file-facing half with ops and a wait queue, and the protocol half with queues, limits and callbacks.
sockfs, socket_file_ops, private_data
The pseudo-filesystem giving sockets inodes; the file operations table; the pointer from file to socket.
sock_recvmsg, inet_recvmsg, tcp_recvmsg
The three indirect calls from a read to TCP.
request socket, accept queue
The mini-socket a SYN creates, and the queue of completed connections accept() drains.
sk_receive_queue
Queue one: in-order data waiting for recvmsg.
out_of_order_queue
Queue two: a tree of segments that arrived ahead of a gap.
socket backlog, sk_backlog
Queue three: segments that arrived while a process held the socket lock; drained by __release_sock.
sock_owned_by_user
The test that picks queue three over queue one.
sk_rcvbuf, sk_rmem_alloc, truesize
The receive memory limit, the running total, and the unit both are measured in.
sk_data_ready, sock_def_readable, sk_wq
The wakeup callback, its default, and the wait queue readers and epoll sit on.
sock_rfree
The receive destructor that returns memory to the socket when the reader frees an skb.

Chapter 8 · Two programs on one host: lo, same pod, unix sockets

loopback_xmit
The loopback driver's transmit function: orphan the skb, pin the route, run eth_type_trans, call __netif_rx.
skb_dst_force
Takes a real reference on the skb's route so it stays valid across the transmit and receive boundary.
skb_valid_dst
The test ip_rcv_finish_core uses to decide whether an input route lookup is needed at all.
PACKET_OUTGOING, PACKET_LOOPBACK
The pkt_type a tap sees on the transmit side, and the one dev_loopback_xmit sets for multicast self-copies so packet sockets discard it.
unix_stream_sendmsg, unix_dgram_sendmsg
The unix socket send paths: allocate an skb, copy the payload, queue it on the peer.
unix_stream_read_generic
The unix socket read path, draining the peer's sk_receive_queue.
sock_alloc_send_pskb
The allocator charging an outgoing skb to the sender's send buffer, which is where unix socket backpressure comes from.
abstract socket
A unix socket whose name begins with a zero byte; it lives in a per namespace hash table rather than on a filesystem.
SCM_RIGHTS, SOCK_SEQPACKET
File descriptors carried in UNIXCB(skb).fp, and the unix socket type with record boundaries plus connections.

Chapter 9 · veth: the mystery, resolved

veth_xmit
The veth transmit function: find the peer, pick a door, forward the same skb.
veth_forward_skb
The three-line function holding both doors, __netif_rx and veth_xdp_rx.
veth_skb_is_eligible_for_gro
The test that reads the sending device's segmentation offload to decide whether aggregating is worth it.
veth_xdp_rcv_skb
The NAPI-side receive function, which runs GRO and enters the IP layer without the backlog.
__dev_forward_skb, ____dev_forward_skb
The shared handoff used by veth and by BPF redirect: check, scrub, then eth_type_trans.
__is_skb_forwardable
The up-and-MTU check, with GSO skbs exempted from the length test.
skb_scrub_packet
Erases the state a packet may not carry into another device or namespace: route, conntrack, input index, and the mark when crossing namespaces.
xnet
The argument telling skb_scrub_packet that the two devices are in different network namespaces.

Chapter 10 · The bridge, and Docker on it

br_handle_frame
The bridge's receive handler, registered per port; it returns RX_HANDLER_CONSUMED.
br_handle_frame_finish
The continuation after the bridge PRE_ROUTING hook, where learning and the forwarding decision happen.
forwarding database
The bridge's MAC-to-port table, read by br_fdb_find_rcu and written by br_fdb_update; bridge fdb show prints it.
br_forward, __br_forward
The one-port forwarding path; __br_forward performs the skb->dev = to->dev assignment.
br_flood, deliver_clone
Delivery to every port for an unknown destination, cloning the skb for all but the last port.
br_dev_queue_push_xmit
Pushes the Ethernet header back and calls dev_queue_xmit on the chosen port.
br_pass_frame_up
Local delivery: set skb->dev to the bridge device and re-enter netif_receive_skb.
NF_BR_ hooks
The bridge family's own hook points, PRE_ROUTING, FORWARD, LOCAL_IN and POST_ROUTING, which ebtables and nftables bridge chains attach to.
br_netfilter
The module that calls the IPv4 and IPv6 chains from inside the bridge hooks and returns NF_STOLEN.
bridge-nf-call-iptables
The per namespace sysctl gating that behaviour; it exists only once br_netfilter is loaded.
ip_sabotage_in
The br_netfilter entry on IP PRE_ROUTING that suppresses a duplicate chain run when a bridged frame later climbs to IP.
DOCKER, DOCKER-USER
Docker's own iptables chains for published-port destination NAT and for operator rules that Docker will not rewrite.

Chapter 11 · Master devices: bond and VRF

bond_handle_frame
The bond's receive handler; it sets skb->dev to the bond and returns RX_HANDLER_ANOTHER.
recv_probe
The bond's hook for control frames, set to the LACPDU or ARP-monitor receiver, called before the data path.
bond_should_deliver_exact_match
The inactive-slave test that answers RX_HANDLER_EXACT so a standby member does not deliver traffic twice.
bond_start_xmit, __bond_start_xmit
The bond transmit entry and the switch on bonding mode that picks a slave-selection function.
bond_dev_queue_xmit
Sets skb->dev to the chosen slave and re-enters dev_queue_xmit, giving one packet two transmit passes.
bond_xmit_hash, transmit hash policy
The slave-selection hash and the choice of which header fields feed it, from MAC-only to addresses and ports.
l3mdev
The layer-3 master device framework a VRF plugs into, with its own receive hook and routing rule.
l3mdev_ip_rcv, vrf_ip_rcv
The call from ip_rcv_finish into the VRF, and the function that relabels the skb and re-runs PRE_ROUTING.
IPSKB_L3SLAVE
The flag marking an skb as having arrived through an l3mdev slave.
vrf_l3_out, vrf_ip_out_direct
The output side, which runs LOCAL_OUT and POST_ROUTING with the VRF device before the real device repeats them.
l3mdev routing rule
The from all lookup [l3mdev-table] rule that sends a lookup to the VRF's own table.
tcp_l3mdev_accept
The sysctl deciding whether a socket outside a VRF may accept connections arriving through one.

Chapter 12 · macvlan and ipvlan

lower device
The existing device a macvlan or ipvlan is built on; it owns the receive-handler slot they take over.
macvlan_handle_frame, macvlan_hash_lookup
The macvlan receive handler and the destination-MAC lookup that picks the upper device.
macvlan modes
private, vepa, bridge, passthru and source: whether and how two upper devices on one lower may talk.
promiscuous lower device
The consequence of a macvlan having its own address: the lower device must accept frames not addressed to it.
ipvlan_handle_frame, ipvlan_addr_lookup
The ipvlan receive handler and the destination-IP lookup that picks the upper device.
ipvlan_get_L3_hdr
The parse step that makes ipvlan a layer-3 demultiplexer; the one line that differs from macvlan in a bench trace.
ipvlan l2, l3, l3s modes
Demultiplex before IP; route on the parent with the parent's output chains; or swap the device inside a LOCAL_IN hook so the parent's conntrack runs first.
ipvlan_process_v4_outbound
The l3-mode output path that does its own route lookup and calls ip_local_out in the parent's namespace.
ipvlan_nf_input
The l3s device swap, registered at NF_INET_LOCAL_IN with priority INT_MAX.

Chapter 13 · IPVS: the NAT that hides in INPUT

virtual service, real server
The address and port clients connect to, and the backends it is balanced across.
director
The host running IPVS, which owns the virtual address as a local address.
ip_vs_in_hook, ip_vs_out_hook
The two family-agnostic hook functions in 7.2, replacing the older per-family names; request direction and reply direction.
ip_vs_ops4
The registration array: two entries on LOCAL_IN, two on LOCAL_OUT, two on FORWARD, with priorities placed around the NAT priorities.
ip_vs_schedule
Finds the service and calls the scheduler module once per connection to pick a real server.
struct ip_vs_conn
The per-connection record holding client, virtual and real addresses and the packet_xmit function pointer.
packet_xmit
The forwarding method stored in the connection: masquerade, direct routing or tunnelling.
ip_vs_nat_xmit
The masquerading method: rewrite the destination, fix checksums, then re-inject.
ip_vs_nat_send_or_cont
The re-injection: set ipvs_property, call the LOCAL_OUT hooks, then dst_output, and report the skb as stolen.
ipvs_property
The skb bit marking a packet IPVS already owns, so the hooks do not act on it again.
direct routing, tunnelling
Forwarding methods that rewrite only the destination MAC, or add an outer IP header, so replies bypass the director.
kube-ipvs0
The dummy device kube-proxy puts every service address on, purely to make the routing decision answer local.

Chapter 14 · Cilium on one node: the tc hook takes over

cil_from_container
Cilium's program on the tcx ingress of the host end of a pod veth pair; it sees packets leaving that pod.
ipcache
The map from IP address to security identity that tells the program what the destination is.
security identity
The number Cilium assigns to a set of labels; policy is written between identities rather than addresses.
policy_can_egress4
The policy check inside the sender's program, before any forwarding decision.
ipv4_local_delivery
The same-node delivery path; it rewrites both MAC addresses for the destination endpoint.
redirect_ep, ctx_redirect_peer
Cilium's choice between an ordinary redirect and the peer redirect, and the helper that performs the second.
bpf_redirect_peer, skb_do_redirect
The BPF helper and the kernel function that swap skb->dev to the veth peer and report -EAGAIN.
ndo_get_peer_dev
The device operation that names a virtual device's other end, letting the redirect work without knowing about veth.
cilium_host, cilium_net
The extra veth pair carrying traffic between the node itself and pods, with cil_from_host and cil_to_host attached.
endpoint routes
The alternative mode that delivers with host routes and a cil_to_container program instead of a peer redirect.
SKB_DROP_REASON_TC_INGRESS
The drop reason a tc program's denial is recorded under, visible in a pwru trace.

Chapter 15 · Cilium across nodes and to the world

encap_and_redirect_lxc
The tunnel branch of the sender's program; it sets the tunnel key and redirects to the tunnel device.
ctx_set_encap_info4, tunnel key
The call that writes the remote node address and the tunnel identifier the encapsulation will use.
tunnel identifier
The VXLAN or Geneve identifier field, carrying the sender's security identity so the far node need not look it up.
cilium_geneve
The tunnel device the sender redirects to; its egress program is cil_to_overlay and its ingress one cil_from_overlay.
outer packet, inner packet
The node-to-node UDP datagram, and the pod-to-pod packet carried inside it; netfilter sees only the first.
geneve_udp_encap_recv
The receive callback on the tunnel's UDP socket; it strips the outer headers and hands the skb to the tunnel device.
gro_cells_receive
How the tunnel device re-enters the receive path after decapsulation.
cil_from_netdev, cil_to_netdev
The programs on the physical device's tcx ingress and egress.
fib_redirect_v4
The native-routing and host-routing branch: do a route lookup in BPF and redirect to the resulting device.
pass_to_stack
The branch that hands the packet to the host stack instead, used when host routing is off.
handle_nat_fwd, snat_v4_nat
Cilium's BPF masquerade, performed in the physical device's egress program with state in a BPF map.

Chapter 16 · Epilogue · Epilogue: traps, fast paths, what came next

flowtable
A netdev-ingress hook that rewrites and transmits packets of an already-seen forwarded connection, skipping FORWARD and conntrack.
netkit
A device pair that runs a BPF program inside its transmit function and delivers to the peer with __netif_rx.
BIG TCP
Raising the segmentation-offload size limit past 64 KB so fewer, larger units traverse the stack.
NF_INET_INGRESS
A netfilter hook at device ingress, before ip_rcv, at the point tc and XDP already occupied.
