References

Every reference cited in the document, deduplicated and grouped by layer, with the chapters that use it. Each one was fetched and its title checked while this document was being written; nothing here is a guessed URL. Use the filter buttons in the how to read card to hide layers you do not need.

Hardware, rings and interrupts HW

  • HWNAPI, kernel documentation. Read the driver API and IRQ mitigation sections; the busy-polling part is optional. Used in chapter 1.
  • HWScaling in the Linux Networking Stack, kernel documentation. The RSS and RPS sections, ten minutes; they also define RFS and XPS, which this document skips. Used in chapter 1, chapter 6.
  • HWPage Pool API, kernel documentation. Skim the architecture overview to see why buffer allocation is off the per-frame path. Used in chapter 1.
  • HWMonitoring and Tuning the Linux Networking Stack: Receiving Data, Packagecloud, 2016. Third-party and written against an older kernel, still the best long walk through this chapter with every sysctl named. Read after you have run the lab once. Used in chapter 1.
  • HWGoing big with TCP packets, LWN, 14 February 2022. BIG TCP, and the measurements that motivated raising the ceiling. Used in chapter 16.

The device layer: taps, tc, bridges, bonds, veth, upper devices L2

  • L2struct sk_buff, kernel documentation. Read the data buffer and cloning sections once now; skip the rest until chapter 3. Used in chapter 0.
  • L2Segmentation Offloads, kernel documentation. The GRO paragraphs; the transmit half returns in chapter 6. Used in chapter 1, chapter 6, chapter 9.
  • L2packet(7), Linux manual page. The first two pages: socket types, ETH_P_ALL, binding to a device, and the promiscuous membership option. Used in chapter 3, chapter 8.
  • L2Packet MMAP, kernel documentation. How tcpdump avoids a copy per frame with a shared ring; skim once, it explains why capture is cheap. Used in chapter 3.
  • L2veth(4), Linux manual page. Short and worth reading once: it states the pair relationship and the namespace behaviour this chapter traces. Used in chapter 9.
  • L2ethtool(8), Linux manual page. The -K option list; tso, gso and gro are the three switches that move the door in this chapter's lab. Used in chapter 9.
  • L2Network Devices, the Kernel, and You!, Linux kernel documentation. The contract a driver's transmit function works under, which is what makes veth_xmit calling a receive function legal. Used in chapter 9.
  • L2Ethernet Bridging, Linux kernel documentation. Short; the section on br_netfilter and its sysctls is the one to read after this chapter. Used in chapter 10.
  • L2bridge(8), Linux manual page. The fdb and link subcommands, which is how you read the forwarding database and the port states this chapter traces. Used in chapter 10.
  • L2Bridge network driver, Docker documentation. What Docker builds on top of the machinery above, including the default bridge and user-defined bridges. Used in chapter 10.
  • L2Linux Ethernet Bonding Driver HOWTO, Linux kernel documentation. Long; read the mode descriptions and the xmit_hash_policy section, which is where a disappointing bond is usually explained. Used in chapter 11.
  • L2IPVLAN Driver HOWTO, Linux kernel documentation. Short and the best statement of when to choose ipvlan; it names the three switch-side reasons directly. Used in chapter 12.
  • L2ip-link(8), Linux manual page. The full macvlan mode list with one-line definitions; the ipvlan entry is thin, so use the HOWTO above for its modes. Used in chapter 12.
  • L2Macvlan network driver, Docker documentation. The operational view, including the warning that your network equipment must accept several MAC addresses on one port and that most cloud providers block it. Used in chapter 12.

IP, routing, netfilter, conntrack and IPVS L3

  • L3File:Netfilter-packet-flow.svg, Jan Engelhardt, CC BY-SA 3.0. Keep it open beside every chapter from 3 to 13; each chapter names which box it is filling in. Used in chapter 0.
  • L3IP Sysctl, kernel documentation. Search for ip_forward, forwarding, rp_filter and ip_early_demux; each entry is a paragraph. Used in chapter 4.
  • L3LC-trie implementation notes, kernel documentation. Ten minutes on how the FIB is stored; read it if you have ever wondered why a million routes lookup in constant time. Used in chapter 4.
  • L3ip-rule(8), Linux manual page. The policy rules fib_lookup walks before the table; the VRF chapter uses one of them. Used in chapter 4, chapter 11.
  • L3Netfilter hooks, nftables wiki. The diagram on that page places the routing decision between the hooks exactly as this chapter's code does; keep it beside chapter 5. Used in chapter 4, chapter 5.
  • L3Netfilter hooks diagram, Pablo Neira Ayuso. One image; the hooks with the routing decisions between them, as the maintainer draws it. Used in chapter 5.
  • L3Netfilter Conntrack Sysfs variables, kernel documentation. Timeouts and table sizes; read nf_conntrack_max and the TCP timeouts when a table fills up. Used in chapter 5.
  • L3nft(8), netfilter.org. The chain types and priorities section, and the ct expression; reference, not reading. Used in chapter 5.
  • L3arp(7), Linux manual page. The neighbour cache sysctls: unres_qlen_bytes, base_reachable_time_ms, gc_stale_time; five minutes. Used in chapter 6.
  • L3RFC 826: An Ethernet Address Resolution Protocol, D. Plummer, 1982. Short, and still exactly what arp_solicit sends. Used in chapter 6.
  • L3Monitoring and Tuning the Linux Networking Stack: Sending Data, Packagecloud, 2017. Third-party and older, but the only long walk through qdiscs and drivers with every counter named; read after the lab. Used in chapter 6.
  • L3Packet filtering and firewalls, Docker documentation. The authority for the DOCKER and DOCKER-USER chains and where they sit relative to your own rules. Used in chapter 10.
  • L3Virtual Routing and Forwarding (VRF), Linux kernel documentation. The setup examples and the section on applications; read it before building anything with ip vrf exec. Used in chapter 11.
  • L3ip-vrf(8), Linux manual page. What ip vrf exec actually does to a process, which is the part people guess wrong. Used in chapter 11.
  • L3Virtual Server via NAT, Linux Virtual Server project. The original description of the masquerading method, with the packet-rewriting diagram this chapter traces in code. Used in chapter 13.
  • L3ipvsadm(8), Debian manual pages. The only interface for configuring virtual services; read the -A, -a and -L forms before the lab. Used in chapter 13.
  • L3IPvs-sysctl, Linux kernel documentation. Every net.ipv4.vs.* knob including conntrack and conn_reuse_mode, which is the one that sends a new connection to a stale backend under connection churn. Used in chapter 13.
  • L3Virtual IPs and Service Proxies, Kubernetes documentation. The IPVS mode section explains the dummy device and the ipset arrangement from the operator's side. Used in chapter 13.
  • L3Netfilter's flowtable infrastructure, Linux kernel documentation. Short, with the configuration that creates the offload; read it before trusting a FORWARD counter on a router. Used in chapter 16.

Sockets, TCP, UDP and unix sockets SOCK

  • SOCKsocket(7), Linux manual page. SO_RCVBUF, SO_SNDBUF, SO_RCVLOWAT, and the rmem_default and rmem_max sysctls; the reference for every limit in this chapter. Used in chapter 7.
  • SOCKtcp(7), Linux manual page. The tcp_rmem autotuning paragraph and somaxconn; skip the option list. Used in chapter 7.
  • SOCKudp(7), Linux manual page. Two pages; the one about buffer errors is the UDP section of this chapter. Used in chapter 7.
  • SOCKrecv(2), Linux manual page. The system call that starts the three indirect calls; read the MSG_DONTWAIT and MSG_PEEK paragraphs. Used in chapter 7.
  • SOCKFlorian Westphal, tcp: remove prequeue support, Linux 4.13 (GitHub mirror). Until 2017 there was a fourth queue; the commit message explains what it did and why it went, which is the best short explanation of why the three that remain exist. Used in chapter 7.
  • SOCKunix(7), Linux manual page. The authority for abstract versus pathname sockets, SOCK_SEQPACKET and SCM_RIGHTS; read the Address format section before the code. Used in chapter 8.

XDP, tc programs and Cilium BPF

  • BPFHøiland-Jørgensen et al., The eXpress Data Path: Fast Programmable Packet Processing in the Operating System Kernel, ACM CoNEXT 2018 (open-access PDF; the source and data are at github.com/tohojo/xdp-paper). Read sections 2 and 3 for the design; the benchmarks are dated. Used in chapter 2.
  • BPFXDP Programming Hands-On Tutorial. Do the basic lessons if you want to write more than the pass program; each lesson is an hour. Used in chapter 2.
  • BPFBPF_MAP_TYPE_DEVMAP and BPF_MAP_TYPE_DEVMAP_HASH and BPF_MAP_TYPE_CPUMAP, kernel documentation. Short; they define the two redirect targets precisely. Used in chapter 2.
  • BPFAF_XDP, kernel documentation. Only if you want the user-space path; the overview section is enough to place it. Used in chapter 2.
  • BPFBPF and XDP Reference Guide, Cilium documentation. The XDP and tc sections of the program types chapter; long, and the best written explanation of the two hook points side by side. Used in chapter 2.
  • BPFtc-bpf(8), Linux manual page. The classic way to attach a BPF classifier; read the direct-action paragraph. Used in chapter 3.
  • BPFDaniel Borkmann, bpf: Add fd-based tcx multi-prog infra with link support, Linux 6.6 merge commit (GitHub mirror), and the series cover letter BPF link support for tc BPF programs (LWN mirror). The commit message is the tcx design document; read it before chapter 14. Used in chapter 3.
  • BPFLife of a Packet, Cilium documentation. The same journey as a diagram, for the endpoint-to-endpoint, egress and ingress cases; read it against this chapter's trace. Used in chapter 14.
  • BPFTuning Guide, Cilium documentation. The eBPF Host-Routing section states in one sentence what the zero in this chapter's table means: it bypasses iptables and the upper host stack. Used in chapter 14.
  • BPFKubernetes Without kube-proxy, Cilium documentation. Read the socket load balancing section: it is the piece that acts before anything in this chapter, at connect() time. Used in chapter 14.
  • BPFbpf/bpf_lxc.c, Cilium source. The file this chapter traces; start at cil_from_container and follow the tail calls rather than reading top to bottom. Used in chapter 14.
  • BPFMasquerading, Cilium documentation. The Implementation Modes section contrasts the eBPF and iptables implementations, which is the difference this chapter measures. Used in chapter 15.
  • BPFRFC 8926, Geneve. Read section 3 for the header and the variable-length options; the identifier field is where the security identity travels. Used in chapter 15.
  • BPFRFC 7348, VXLAN. The older and simpler encapsulation, for comparing the two header layouts. Used in chapter 15.
  • BPFVirtual eXtensible Local Area Networking documentation, Linux kernel documentation. The kernel side of tunnel devices, including the external-control-plane mode Cilium drives from BPF. Used in chapter 15.
  • BPFJonathan Corbet, The BPF-programmable network device, LWN, 6 November 2023. The introduction of netkit and why a tc hook on a veth pair was one step too late. Used in chapter 16.
  • BPFBPF link support for tc BPF programs, LWN. The tcx design and the attachment problems it was built to fix. Used in chapter 16.
