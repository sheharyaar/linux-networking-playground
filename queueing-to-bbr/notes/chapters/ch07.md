## Spine and strands
Spine: one 1500-byte packet of a VM's paced TCP flow, in an aggregate held to 1 Gbit/s, on the paper's evaluation wheel (2 µs, 2 s, p. 413): TCP stamp 5.000004 s, aggregate stamp 5.000302 s, slot 2,500,151, index 500,151, released at its slot, completion lets the flow send the next.
Strands (= h3 ids = quiz lists):
- `queue-per-limit` — A queue and a lock per rate limit
- `release-times` — A rate written as a release time
- `timing-wheel` — A wheel of time slots
- `slot-and-horizon` — Slot width and horizon
- `deferred-completions` — Completions held until the wire
- `wheel-per-core` — One wheel per core

## Measured on the bench
Rootless, kernel 7.2.6-arch2-1, HZ = 1000, 2026-10-02, shared CPU. Data: `labs/ch07-carousel/data/` (README there).
- Timer wheel (`wheelwait.py`): every SO_RCVTIMEO wait came back under its level's slot width (1/8/64/512 ms): 5 s timeout up to 473 ms late, 50 ms at most ~1 ms. hrtimer (`time.sleep`) ~0.1 ms. Quick run: one 200 ms wait at 10.85 ms (slot + scheduling noise; hrtimer column shows noise up to ~1 ms in that run).
- Wheel vs heap (Python, starter driver + page solution): heap comparisons/packet 8.8, 12.1, 15.4, 18.8 at 200, 2K, 20K, 200K queued (≈ log2 n + 1); wheel 4.0–4.1 throughout. ns/packet heap 528 → 2,522; wheel 529 → 1,275 (shared CPU; heapq is C). Wheel error −1.0..+1.0 µs (releases up to one slot early).
- Algorithm 1 as printed: poll every slot 11,627 of 20,000 released within 20× the needed time, up to 0.38 s late; poll every 3rd slot 53. Slip (b) fixed only: 20,001 but up to 765 µs late (poll 1), 109 (poll 3). Both fixed: all, within one poll interval.
- 16 Reno flows × 500 kbit/s: HTB on s0 and fq maxrate on s0 both hold 32 skbs = 96,896 B, RTT 137 ms, 0 retrans, wmem_alloc 7,712 B (2 truesizes); HTB on r1 (TSQ blind, netem on s0 orphans): median 926 pkts / 1.40 MB, max 1,600 / 2.42 MB, RTT 1.24–2.47 s (median 1.74), 1,614 retrans. Output 8.007 / 7.990 / 8.002 Mbit/s. The router in the s0 runs carries the 20 ms delay and no rate, so the shaper is the only queue. A second set in `data/ackpath/` follows the coordinator's later recipe (r1 as qnet built it, 40 ms on the acks): same memory and rates, RTT 155 ms median (130–174) because the 10 Mbit/s hop queues the 16 classes' synchronised two-frame bursts at 80% load. The page uses the first set.
