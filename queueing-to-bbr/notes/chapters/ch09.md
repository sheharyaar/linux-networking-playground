## Measured on the bench
Rootless, kernel 7.2.6-arch2-1, Ryzen 7 8845HS laptop shared with other builders' runs. Data in `labs/ch09-eiffel/data/` (README there).
- C race (hold model; pop min, push a new packet 1..N−1 buckets later), 20,000 buckets, 3 → 1,000,000 packets queued: cFFS 13.7–20.2 ns per pop+push (4.0–9.5 words); binary heap 7.2 → 122.6 ns (2.0 → 38.4 comparisons); slot-by-slot wheel 4,886 ns (3,347 slots) → 13.4 ns; one bit per slot 9.9–27.9 ns. Heap beats cFFS below ~20 packets (n=10: 13.8 vs 16.7; n=30: 19.8 vs 14.6).
- Same race over buckets: at 1,000 packets the one-bit scan beats cFFS up to 1M buckets (9.9–15.9 vs 14.5–37.4 ns) and ties at 4M (72 vs 67 ns, memory-bound); at 10 packets cFFS wins once sparse: 1M buckets scan 233 ns vs cFFS 40 ns, 4M buckets 882 vs 69 ns; heap ~14 ns throughout (n=10). Honest reading: the bitmap's main win over a timing wheel is 64 slots per read; the hierarchy's win is the bound when the window is sparse.
- Python lab (solution at six sizes): 3.65–5.5 words per pop (3 levels), heapq 2 → 15.35 comparisons per pop as n grows; heapq faster on time (275 vs 973 ns at 1,000 packets) because it is C.
- Rootless build of the selftest BPF fq qdisc with clang 22 + bpftool 7.8: works (object 1,053,752 bytes, 4 struct_ops programs). clang lowers `__builtin_ctzll` for BPF to x & −x, multiply by 0x218a392cd3d5dbf, >> 58, table load.
- Order checks: `race.c -DCHECK` verified every queue pops in non-decreasing rank.

## Errata and since-the-paper notes
Errata shipped (all re-verified on rendered pages):
- p. 21: "Bit-Scan-Forward (BSR)": BSF is forward (lowest set bit), BSR reverse (highest); a min queue needs BSF/tzcnt (`__ffs`). "Leftmost" is the figure's drawing convention. (p. 23's BSR fits the max-seeking gradient queue.)
- p. 19: the second "non-work conserving" (timing wheel lacks ExtractMin) should be work-conserving.
- p. 22: curvature written ax² − bx + c with critical point b/2a, but with b = Σ i·2^i the form is ax² − 2bx + c and the critical point b/a; the slips cancel and ceil(b/a) is right. Literal b/2a gives 1.73 → bucket 2 for {1,3,4} (true max 4).
Held (not shipped, budget): p. 28 says "Figure 12 shows throughput … for different ratios of non-empty buckets", which is Fig. 13; line rate "20 Gbps" in §1 (p. 18) vs 25 Gbps instances / 24 Gbit/s aggregate on p. 26; Appendix A uses N both as bucket count and max index.
Since the paper (v7.2, 2 Oct 2026): x86 `__ffs` = tzcnt (spelled rep;bsf before v6.16), `__fls` = bsr; `find_first_bit` is a word scan; RT scheduler still two `__ffs`; QFQ shifts its slot bitmap, the timer wheel does a two-part search; sch_fq still rb-tree for throttled flows + per-flow t_root since v5.2; BPF qdiscs since v6.16 with fifo and fq selftests (bpf fq also uses bpf_rbtree for delayed flows and per-flow packets); bits iterator kfunc v6.11 (≤ 511 words); no Eiffel/cFFS code upstream (`git grep -i eiffel` only hits sound/pci/ad1889.c).
